# 故障排查

> 什么时候读这份：任何一步报错、端点不通、结果看起来不对。
> 先定位卡在哪一步：stderr 日志每行都有 `[probe]` / `[extract]` / `[vlm]` / `[timeline]` 前缀，看最后出现哪个。

## 依赖问题

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `[run] ERROR: 未找到 ffmpeg/ffprobe` | 没装 ffmpeg | Ubuntu/Debian `apt install ffmpeg`，macOS `brew install ffmpeg`，装完重跑 `scripts/install.sh --offline` 复核 |
| `[probe] ERROR: 未找到 ffprobe` | 同上 | 同上 |
| 装的时候提示缺 Pillow | Pillow 是可选的 | 不装也能跑，只是拼图没有时间戳标注。想加上就 `pip install Pillow` |

## 视频 / 抽帧问题

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `视频文件不存在` | 路径写错或用了相对路径 | 找用户要绝对路径，这个 skill 不猜 |
| `无法从 ffprobe 获取视频时长` | 文件损坏、不是视频、或者是个流地址 | 用 `ffprobe 视频路径` 手动确认文件完整 |
| `抽帧失败：未生成任何帧` | 编码太冷门或时长太短 | 换 H.264 编码的输入；确认时长够 |
| `分析范围过短: 范围 X.Xs 按 Ns 间隔抽不出任何帧` | 范围 ÷ 间隔不足一帧 | 扩大范围，或调小 `--interval` |
| `按 Ns 间隔将产生 M 帧，超过上限`（WARN） | 帧数超了 `--max-frames` | 保护行为，不是错误。真需要更多帧就调大上限 |

## 端点 / VLM 问题

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `端点不可达` / Connection refused | vLLM 没起 | `curl http://127.0.0.1:8000/v1/models` 确认服务；急用就 `--no-vlm` 先出结构 |
| `无法列出模型 … 沿用 'auto'` | `/v1/models` 请求失败 | 先 curl 看端点到底通不通；通了就用 `--model <名字>` 显式指定 |
| auto 挑了个纯文本模型 | 端点上只有文本模型 | `--model` 指定带视觉能力的（名字一般含 vl/vision/video） |
| 一堆 `t=…s FAIL` | 超时、单帧太大、或模型不认图 | 调大 `FOOTAGE_GUARD_TIMEOUT_S`；换支持图像输入的模型。失败的帧下次重跑会补上（成功的已缓存） |
| `[vlm] WARN: 端点不是本机地址` | 指向了远端服务 | 画面要出网，先征得用户同意；本地场景改回 127.0.0.1 |

## 结果 / 时间线问题

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 事件切得太碎 | 人数/车辆档位在相邻帧间抖动 | 启发式聚合的固有现象。调大 `--interval`，或者接受"需人工复核"的标注 |
| 一个关注事件都没有 | 关键词没命中 | 用 `FOOTAGE_GUARD_KEYWORDS` 换成你场景里的词；也可能确实没异常 |
| 时间线是覆盖性占位（结构模式） | VLM 没启用或全部失败 | 起好端点去掉 `--no-vlm` 重跑；先 `vlm_describe.py --dry-run` 定位端点问题 |
| 时间戳和画面对不太上 | 关键帧按间隔近似落点 | 间隔调小会更准；报告里已标注需人工复核 |

## 通用

- 排查顺序：probe → extract → vlm → timeline，一步过再看下一步。
- 复跑成本低：成功的帧描述都在 `frames/*.json` 里，只有失败帧和新帧才再调端点。
- 想看某帧模型到底说了什么：直接读 `frames/frame_XXXX.json` 的 `desc` 字段。
